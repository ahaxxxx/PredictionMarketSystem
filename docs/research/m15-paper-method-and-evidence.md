## 2. 方法中的对象分别是什么

一个候选是“已有因子的组合配置＋入场门槛”。本版没有生成新 Python 策略，没有组合 anchoring/flb/ripple 三套完整策略，也没有改变原交易系统的并发架构。

为描述当前候选，记：

$$
\theta=(w_1,\ldots,w_d,h),\qquad
p_\theta(x)=\operatorname{clip}\left(q+\sum_{j=1}^d w_j\delta_j(x),\epsilon,1-\epsilon\right).
$$

- $x$：一个决策时刻可用的搜索特征。
- $q$：该时刻市场 YES 概率价格。
- $w_j$：第 $j$ 个因子的修正权重。
- $\delta_j(x)$：组合器实际使用的修正输入；本版允许的标量因子取原值，概率因子取其概率减 $q$。
- $h$：预测与市场价之间的入场门槛。
- $\epsilon=10^{-6}$；`clip` 将预测限制在 $[\epsilon,1-\epsilon]$。

这个公式对应本版受限的 `rule_delta` 配置，不能拿来概括仓库其他组合角色和完整策略家族。实际预测始终调用原组合器，公式不是另写的一套执行逻辑。

M1 输出原有 `CandidateSpec`；M5 的新增记录在旁边保存。记录之间通过候选 ID、诊断 ID、建议 ID 和证据 ID 关联。配置 ID 由实际参数决定，提议理由不会把同一参数配置变成新候选。

## 3. M5 已实现的机制

### 3.1 先计算证据

对搜索特征上的有效输入，计算激活比例：

$$
a_j=\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}\{|\delta_j(x_i)|>10^{-12}\}.
$$

$N$ 是搜索特征观测数量；$\mathbf{1}$ 表示条件成立记为 1，否则记为 0。$a_j=0$ 说明这批特征中未出现超过容差的有效输入，不能据此断言这个因子在其他事件上无用。

同时记录组合预测落在概率上下边界的比例，以及 M2 已报告的开发 Brier。Brier 衡量预测概率与结算结果之间的平方误差，越低越好；它是已有标签参与的评价摘要。

因此，准确说法是：**特征激活和行为检查不新增读取结算结果；整个 M5 反馈并非完全无标签。**它仍接收已有 M2 Brier。当前结构化诊断没有消费 M3 收益；原人工报告仍展示已有慢评结果。

每条证据保存数据指纹、轮次、候选、目标、指标定义、数值和样本数。旧反馈没有 M2 的实际评分点数，因此 Brier 证据的样本数标为未知，不自动假设等于特征面板大小。

### 3.2 再产生有限的修改建议

目前由确定性规则生成三种操作：

| 操作 | 触发条件 | 含义 |
|---|---|---|
| `freeze` | 某因子的有效输入全为零 | 本次受约束局部提议不改该维度；原随机探索仍保留 |
| `toward_zero` | 有预测触及边界，且目标权重非零 | 提出减小该权重幅度的试验建议 |
| `explore` | 其他有效输入，或比较入场门槛 | 允许在已声明空间中比较参数，不预先断言方向优劣 |

边界比例是组合后的结果，规则没有证明某个因子造成了饱和。向零调整也可能使预测变差，必须通过评价验证。

当前每条建议都附带不确定性和供人理解的证伪描述；**尚未实现自动跟踪并判定一个经济假设被证实或证伪的管理器**。不能把这些文字字段写成已完成的自动科学发现系统。

代码：[特征证据计算](../../src/pms/optimizer/evidence.py) · [M5 `build_review()`](../../src/pms/optimizer/m5.py)

## 4. M1 已实现的机制

### 4.1 将提议约束为可检查的参数操作

每条提议包含：父候选 ID、目标参数、新值、建议 ID、证据 ID、声明的参数增减方向和简短假设。编译器一次只改变一个权重或全局门槛，然后生成原 `CandidateSpec`。

编译器允许已声明网格中的合法目标值；本版离线参考提议器进一步只选择相邻值。尚未实现双父代交叉或新规则结构生成。

### 4.2 三类检查

**格式和空间检查**：限定响应大小、字段、提议数量、有限数值、父代、因子/门槛和参数网格；不默默修正非法参数。

**引用和操作检查**：建议、证据、父候选与目标必须匹配；被冻结的维度不允许局部修改；声明“增大参数”时新值必须大于旧值；`toward_zero` 必须减小绝对值。

这里验证的是机器可读的参数关系。假设字段仍是自由文本，**没有实现从任意自然语言经济解释到完整逻辑约束的理解与证明**。

**配置与行为检查**：拒绝已登记的相同配置；对父子候选在同一搜索特征上计算预测和拟交易动作：

$$
b_\theta(x)=\bigl(p_\theta(x),u_\theta(x)\bigr),
$$

其中 $u_\theta(x)$ 为买 YES、买 NO 或不入场，按照 $p_\theta(x)-q$ 的方向及是否达到 $h$ 决定。若所有观测上的这两个量都相同，则拒绝这次外部提议。

改变权重时关注预测；仅改变 $h$ 时，预测保持不变，但入场行为仍可能变化。本版采用实际计算值的精确比较，没有单独设置行为差异容差，也没有跨所有候选建立行为等价类。这个检查不模拟真实订单成交或流动性约束。

### 4.3 保持连续运行

合法外部候选先通过规范配置检查，再进入原 M1 登记表。后续 L2 能接收这些候选的反馈。非法提议被记录，剩余批次用 L1/L2 补足；每轮最多请求后端一次，失败调用也计入调用预算。

正常批次为 L1/L2 保留至少一个名额；空间不足时按实际剩余配置结束。本版没有无限补抽，也没有为失败提议赠送额外候选评价。

代码：[提议解析与编译](../../src/pms/optimizer/llm_proposer.py) · [候选登记与反馈](../../src/pms/optimizer/m1.py) · [离线后端及调用统计](../../src/pms/optimizer/llm_client.py)

## 5. 闭环实际如何衔接

离线优化子循环每轮执行：

```text
候选配置
  → 原 M2 快评、M3 慢评、M4 归档
  → M5 构建证据、诊断与建议，保存为 review
  → 下一轮 ProposalRequest 携带上一轮 review
  → 后端返回受限参数提议
  → 程序校验、编译、登记
  → 新一轮评价
```

第一轮没有上一轮复盘，使用原 L1/L2 产生候选。运行入口检查下一轮读取的 review 是否来自上一轮、是否具有匹配的数据指纹和开发范围。角色与指纹检查不能独立证明数据未被人为误标，事件清单仍需团队核对。

保存内容包括请求、原始响应、接受/拒绝原因、候选注册表、评价结果、结构化复盘、人工报告、输入指纹和优化器代码指纹。额外的特征回放次数也单列。

代码：[运行入口](../../src/pms/optimizer/run.py)

## 6. 一条具体的端到端实例

来自已有 NFL 历史开发回放，完整记录见 [实例 JSON](evidence/m15-v1/feedback-to-candidate-example.json)。

1. 第一轮记录：盘口因子在 32 个观测点均有超过容差的有效输入，激活比例为 1。
2. M5 提出允许比较盘口因子权重的建议，附带证据与父候选 ID。
3. 第二轮离线响应引用该建议，将某个父候选的盘口权重从 0 改为 -0.25。
4. 另一个因子权重仍为 0，入场门槛仍为 0.02。
5. 编译器确认方向、网格、引用及行为变化，登记新候选。
6. 新候选进入原 M2—M4，实例同时保存父子快评与晋级结果。

这条记录证明建议被真实消费、配置被修改并被评价。它不证明“盘口应当取负权重”，也不是一次独立的因果或泛化实验。

## 10. 为形成论文贡献，下一步应验证什么

候选研究假设是：**把复盘证据转成明确修改建议，并核查执行行为，能否在相同候选评价预算下提高搜索效率与独立事件表现？**它是研究问题，不是当前实验结论。

建议依次推进：

1. **接清数据协议。** M2 仅使用搜索事件，M3 使用事件族隔离的开发验证数据；最终测试独立于优化器。若开发验证结果反馈给提议器，应明确其也属于开发信息。
2. **接一种真实模型。** 固定模型版本、提示词、调用和输出上限，补全 token、费用与超时记录；区别模型失败和有效提议。
3. **先比较三种提议。** 原 EA、数值反馈 LLM、证据反馈 LLM，使用同一空间、初始条件、费用与评价预算。
4. **区分规则与 LLM 的作用。** 加入规则诊断＋EA，以及相同证据下的反馈形式和行为检查消融。结构化与自由文本组应收到相同底层事实，避免把更多信息当成格式优势。
5. **验证机制与泛化。** 记录合法性、重复、行为无效、修复成功和评价效率，再在未反馈的独立事件上评价。不能用当前单事件和单种子功能运行替代统计效果实验。

本版行为拒绝检查只在新增提议路径上执行。正式比较时必须使这项检查成为各组共同条件，或明确列为消融因素；不能把不对称的规则优势归给模型。

优先讨论的团队决定：事件族和标签可用时间如何划分；公共 M2/M3 接口如何传入两份数据；哪些质量指标和费用口径先固定；真实模型预算如何设置；什么幅度的改善才值得继续扩展策略结构。
