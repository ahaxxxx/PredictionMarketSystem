## 1．我们现在想完成什么

近期先搭通一个简单、不依赖 LLM 的离线循环：

```text
M1 提出候选
  → M2 快速评分并筛选
  → M3 慢速验收
  → M4 保存成绩与冠军版本
  → M5 基础复盘与结构化反馈
  → M1 提出下一轮
```

原设计还包括 Sensor 因子面板输入、Evaluator 结算与执行证据输入，以及冠军向 Controller 注册。当前功能演示尚未连接后两条边。

长期希望检验：复盘反馈能否在相同预算下，帮助搜索到新事件、新时间段上更有效的组合，再据此形成研究贡献。当前不主张真实盈利、稳定泛化或达到论文投稿条件。

## 2．目前哪些部分已实现

| 模块 | 现有实现 | 当前边界 |
|---|---|---|
| M1 | L1 随机、L2 单维变异、父代保存、稳定候选编号、去重 | 固定因子与角色，只搜索权重和交易门槛；L3 暂缓 |
| M2 | 因子面板回放、方向准确率、Brier、log loss，选 Top-K | 覆盖率口径与门槛接入待核对 |
| M3 | 每点一份合约的交易模拟，含简化费用、滑点和时间切片 | 尚非完整资金/盘口回测；后半窗口不是独立最终留出 |
| M4 | SQLite 候选、成绩和冠军版本档案，支持导出 | 未注册或激活线上策略 |
| M5 | 逐轮成绩、父代、慢评状态、真实晋级理由、模板复盘 | 基础展示；丰富归因与原 Evaluator 证据接入后置 |
| 多轮入口 | 真正调用队友 run_once，连续传递反馈、保存报告 | 支持合成演示和规范化历史开发JSON；公开小样例已接通 |

固定搜索空间：订单簿失衡与 Metaculus 先验，两者角色均为 `rule_delta`。每个权重有 5 个取值，交易门槛有 3 个取值，共 75 个配置。策略池的资金组合并未在本版实现。

原结构化反馈由 `loop._feedback()` 产生，M5 第一版将其呈现为报告；M1 读取同一份数值反馈。父代完整配置由 M1 实例保存，不依赖反馈反推，也不从 Markdown 解析参数。

## 5．有三处想一起核对

### A．覆盖率的计算方式

我看到目前分子按成功评分的时间点计数，分母按因子记录行数计数。一个时间点有多条因子记录时，即使全部评分成功，覆盖率也可能显示偏低。

例如 10 个时间点，每个点有价格和因子两行，总计 20 行。当前算成 `10 / 20 = 50%`，但如果这 10 个点都成功评价，按时间点理解应为 100%。这也已经用小样例复现。

**想确认：是否将分子、分母统一按应评分时间点计算？**

位置：[fast_loop.py 的覆盖率计算](../../src/pms/optimizer/fast_loop.py#L51)。新 IC 分支的对应计算在本次差异中未见调整。

### B．快评和慢评的检查规则

两个模块都写了 `passes_gate()`，但当前主循环直接选 Top-K、做慢评，再交给冠军池自己的规则。这两个检查函数目前没有被调用。

可以理解为：“排名前三”与“达到最低要求”是两个条件。即使候选排名靠前，也可能没有达到数据覆盖或交易数要求。M4 有自己的检查，但不覆盖全部前置条件。

**想确认：是否接成“快评检查 → Top-K → 慢评检查 → 冠军比较”，并保留具体未通过原因？**

位置：[loop.py 的 run_once](../../src/pms/optimizer/loop.py#L71)。

### C．筛选数据与检验数据的划分

目前 M2 用完整面板选候选，M3 再把其中后半段标为 OOS。这部分成绩已经影响候选选择，可能不适合再当作独立检验。

例如：根据 1 月与 2 月的成绩选策略，再把 2 月成绩当新考试，考试就不独立了。这里指选择过程使用了这部分答案，不必然表示预测函数直接读取未来结果。

**想确认：后续接真实数据时，是否先划分用途，用开发数据搜索，再用没有参与选择的数据检验？** 反复用于修改策略、提示词或反馈机制的数据，都应视为开发的一部分。

这三处不妨碍我们先做框架演示，可以一起确认后调整；本次 M1/M5 没有改动原核心代码。
